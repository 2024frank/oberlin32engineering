A workable project cycle

Define, build, test, and leave useful notes.

The process should be light enough for students to use and clear enough that a project can continue after one person graduates.

Define

Write the problem

Name the user or setting, the constraint, the evidence you need, and what is out of scope.

Prototype

Build the smallest test

Choose a version that can answer one important question before the team commits to a larger design.

Test

Record what happened

Save measurements, failures, photos, code, design files, and the decisions that changed the direction.

Share

Make the next step clear

Demonstrate the result, publish a short build note, and explain what another team should try next.

Bring an idea

Start with the problem, not the gadget.

A good proposal can be technical, social, environmental, artistic, or accessibility-focused. It should explain who benefits, what would be tested, and what a small first version might look like.

Do not worry about having every skill. A project brief is also a way to find people with the skills you are missing.
